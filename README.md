# WB Sales Telegram Bot

Текущая версия сборки: **2026.11.05.2**. Она показана в главном меню `/menu` и `/start`.

## Выгрузка добавлений в корзину

В главном меню нажмите **«Выгрузить добавили в корзину»** (также `/cart`), затем выберите период и кабинет. Периоды: «месяц» = 30 дней, «3 недели» = 21 день, «2 недели» = 14 дней, «1 неделя» = 7 дней. Все периоды — полные дни по вчера включительно, по Москве.

Бот отправляет XLSX только в чат, где пользователь из белого списка запросил выгрузку. Столбцы: **ШК, Артикул продавца, Добавили в корзину, Заказали**. Статистика получена за выбранный период из воронки продаж, а не из почасового отчёта. Показатели относятся к карточке WB: все её ШК перечисляются в одной ячейке, показатели не умножаются на количество ШК. Разные карточки с одинаковым артикулом продавца не объединяются. У отсутствующих в текущем каталоге карточек сохраняется статистика, а вместо ШК указано «ШК не найден». Числа не заменяются нулями при неполном ответе WB. ШК и артикулы сохраняются текстом, включая ведущие нули.

Для новой функции нужны категории токена **Аналитика** и **Контент**. Можно использовать токен `WB_TOKEN_1`/`WB_TOKEN_2` с нужными правами или заполнить новые необязательные переменные `.env`:

```env
WB_ANALYTICS_TOKEN_1=...
WB_CONTENT_TOKEN_1=...
WB_ANALYTICS_TOKEN_2=...
WB_CONTENT_TOKEN_2=...
```

Каждая пара должна принадлежать тому же кабинету, что соответствующий `WB_TOKEN`. Пустые значения означают использование `WB_TOKEN` соответствующего кабинета. Доступ не проверяется до первого запроса выгрузки; при недостатке прав бот сообщает, какую категорию проверить.

Источник показателей: `POST https://seller-analytics-api.wildberries.ru/api/analytics/v3/sales-funnel/products`, поля `data.products[].statistic.selected.cartCount` и `orderCount`. ШК сопоставляются по nmId с карточками `POST https://content-api.wildberries.ru/content/v2/get/cards/list`, поле `sizes[].skus`. Используется пагинация обоих методов. Интервалы запросов: 21 секунда для аналитики, 650 мс для контента; для базовых токенов WB может требоваться больший интервал — при 429 выгрузка останавливается с сообщением, неполный файл не отправляется.

Данные воронки обновляются с задержкой и могут уточняться. Формирование идёт в фоне и не блокирует обработку других команд. Во время выгрузки повторный запрос пользователя отклоняется. Файл формируется в памяти без хранения токенов или временных отчётов на диске. Новых зависимостей для XLSX не требуется.

После обновления кода перезапустите бота и откройте `/menu`: должна появиться версия **2026.11.05.2**. Сохраните существующие `.env` и `activity_settings.json`.

Telegram-бот для двух кабинетов Wildberries. Каждый час, в `XX:00` по Москве, бот отправляет **два отдельных сообщения** — по одному на каждый кабинет.

## Что считает

- **Заказов FBO / FBS** — разбивка заказов по модели склада WB (`Склад WB` = FBO, `Склад продавца` = FBS).
- **Заказано итого** — все заказы, оформленные за текущие сутки, включая заказы, которые позднее были отменены.
- **Сумма заказов** — сумма строго выбранного через `/sumprice` поля (`finishedPrice`, `priceWithDisc` или `totalPrice`), без подмены другим полем.
- **Выкуплено итого** — реальные продажи за текущие сутки. Возвраты не считаются.
- **Сумма выкупов** — сумма финальной стоимости реальных продаж по той же логике цены. Возвраты в сумму не входят.
- Ниже выводится разбивка **только по заказам**: `артикул продавца — количество — стрелка динамики`.
- Артикулы с нулём не выводятся.
- Отчёт накопительный: с `00:00` текущего дня до текущего момента.
- Часовой пояс расчёта: `Europe/Moscow`.

## Используемые методы Wildberries

Токен WB должен иметь доступ к категории **Статистика**.

- `GET https://statistics-api.wildberries.ru/api/v1/supplier/orders`
- `GET https://statistics-api.wildberries.ru/api/v1/supplier/sales`

Для текущего дня используется `dateFrom=YYYY-MM-DD&flag=1`.

Заказы вчерашнего дня запрашиваются отдельно с `flag=1`, затем отбираются с 00:00 до того же времени по Москве, что и сегодняшний отчёт. Например, отчёт на 14:00 сравнивает заказы до 14:00 обоих дней. Граница времени включена; сравнение выполняется отдельно для каждого кабинета и артикула. Повторные записи с одинаковым `srid` не удваивают количество; отменённые заказы учитываются, как и прежде.

После количества отображается цветная стрелка:

- `🟢⬆️` — рост больше 15% относительно вчерашнего количества;
- `🟡➡️` — изменение в пределах ±15%, включая границы;
- `🔴⬇️` — снижение больше 15%.

Например, при 12 заказах вчера: 11 сегодня — `🟡➡️`, 10 — `🔴⬇️`, 14 — `🟢⬆️`. Если вчера заказов артикула не было, а сегодня есть, показывается `🟢⬆️`. Артикулы без сегодняшних заказов по-прежнему не выводятся. Поля цены на стрелку не влияют.

Пример строки: `ABC-001 — 11 шт. 🟡➡️`.

Ограничение частоты WB соблюдается общей очередью запросов заказов внутри каждого кабинета: между запросами выдерживается 65 секунд. Поэтому подготовка отчёта без свежего кеша занимает примерно на минуту больше для каждого кабинета. Кеш разделён по дням и кабинетам; данные соседнего дня не подставляются при ошибках. Если данные получить не удалось, бот сообщает об ошибке, а не показывает выдуманную динамику.

## Установка

Рекомендуется Python 3.11+.

```bash
python -m venv venv
```

Linux/macOS:

```bash
source venv/bin/activate
```

Windows:

```bat
venv\Scripts\activate
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

## Настройка

Скопируйте `.env.example` в `.env`:

```bash
cp .env.example .env
```

На Windows можно просто создать копию файла вручную.

Заполните:

```env
TELEGRAM_BOT_TOKEN=...

WB_TOKEN_1=...
WB_NAME_1=СПб-ТТ

WB_TOKEN_2=...
WB_NAME_2=СПб-ТТ Групп
```



## Итоговый отчет за вчера

Пункт меню **«Итоговый отчет за вчера»** (`/yesterday`) отправляет два отдельных отчёта за полные вчерашние сутки по Москве — с 00:00 до конца дня. Результат получает только пользователь, вызвавший команду; требуется доступ по белому списку. Команда работает независимо от часов активности автоматической рассылки.

Формат, FBO/FBS, заказы, выкупы и список артикулов сохраняются. Сумма заказов рассчитывается по текущему выбору `/sumprice`. Стрелки сравнивают полные вчерашние сутки с полными позавчерашними, с допуском ±15%. Это оперативные данные WB на момент запроса: поздние корректировки WB могут изменить итог при повторном запросе.

Почасовая рассылка по-прежнему показывает текущий день. После обновления файлов перезапустите бота, чтобы новый пункт появился в меню Telegram.

## Выбор способа расчёта суммы заказов

Команда `/sumprice` открывает переключатель:

- `finishedPrice`
- `priceWithDisc`
- `totalPrice`

Выбранное поле используется только для строки «Сумма заказов» и сохраняется в `activity_settings.json` после перезапуска. Для чистого сравнения с личным кабинетом бот складывает именно выбранное поле без автоматической подмены другим ценовым полем.
